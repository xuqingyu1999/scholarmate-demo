# ScholarMate 试用说明与商业流程

## 1. 项目定位

ScholarMate 当前是一个静态前端原型，用来演示买方企业如何通过平台完成：

- 企业注册与小额打款认证
- 购买买方企业服务包
- 上传或填写技术需求
- 获得专利与数字顾问推荐
- 购买单项资料/对话许可
- 与数字顾问多会话沟通
- 提交交易意向，进入后续商务跟进

当前版本不接真实后端、真实支付、真实工商认证、真实合同或真实专利数据库。所有业务状态保存在浏览器 `localStorage` 中，LLM 演示配置保存在 `sessionStorage` 中。

## 2. 如何运行

推荐用本地静态服务器运行，而不是直接双击 HTML 文件。

```bash
cd scholarmate
python -m http.server 8123
```

然后打开：

```text
http://127.0.0.1:8123/index.html
```

如果要看手机版预览：

```text
http://127.0.0.1:8123/index.html?mobile=1
```

## 3. 页面入口

- `index.html`：首页与入口页
- `patent-list.html`：专利发现、自然语言搜索、上传需求文本
- `patent-detail.html`：专利详情、资料/对话许可、交易意向、预约真人
- `membership.html`：买方企业服务包
- `user-center.html`：企业认证、需求项目、交易意向、数字顾问资产、会话历史
- `chat.html`：数字顾问对话、多会话、可选 LLM 配置
- `patent-publish.html`：专利发布方表单演示

## 4. 推荐演示流程

### Step 1：进入用户中心

打开 `user-center.html`。如果浏览器里还没有用户状态，系统会自动生成一个企业用户演示账号。

在“企业认证”页签里提交企业名称、联系人、开户行和对公账号。系统会模拟一个小额打款金额，输入正确金额后认证成功。

认证成功后，企业可以购买会员、购买资料/对话许可、提交交易意向。

### Step 2：选择会员服务包

打开 `membership.html`。

当前会员口径是买方企业服务包，不是单纯“买数字人”。

- 免费认证版：2 个技术需求项目，0 个长期顾问席位，每日 100 Token
- 专业版：8 个技术需求项目，10 个顾问席位，每日 500 Token
- 企业版：30 个技术需求项目，不限顾问席位，每日 2000 Token

免费认证版可以试聊免费共享专利，但不能长期保存数字顾问席位。专业版/企业版才包含长期顾问席位。

### Step 3：上传或填写技术需求

有两个入口：

- `patent-list.html` 搜索框下方的“上传需求文本”
- `user-center.html#demand-projects` 的技术需求项目表单

上传需求第一版支持 `.txt` 和 `.md`，也可以直接粘贴正文。系统会自动推断需求标题、行业、阶段和摘要，并创建一个需求项目。

适合测试的需求文本：

```text
基层医院影像诊断效率提升
希望用 AI 医学影像能力提升基层医生诊断效率，优先考虑可快速试点、可解释性较强的方案。
```

也可以测试：

```text
电池高温安全和热失控
准备采购评估新能源电池热管理方案。
```

```text
隐私保护 医疗数据 上链
需要调研多机构医疗数据不出域协同建模。
```

### Step 4：查看推荐结果

推荐采用“语义向量 + 字段权重 + 业务规则”的混合逻辑。

如果浏览器能访问 jsDelivr 和 Hugging Face，会尝试加载 `Xenova/multilingual-e5-small` 做本地 embedding。加载失败时会回退到本地规则推荐。

推荐结果会展示：

- 匹配分数
- 为什么推荐
- 适配场景
- 风险提示
- 下一步动作

为了避免硬凑结果，低相关专利不会因为免费共享或已购许可被顶进 Top 5。

### Step 5：进入专利详情

在 `patent-detail.html` 中可以看到：

- 免费共享专利：显示“免费共享 / 可先沟通”
- 付费专利：显示资料/对话许可年费，例如 `¥1,999/年`、`¥2,999/年`、`¥3,999/年`

资料/对话许可不是法律意义上的专利授权或转让，只是解锁深度问答、资料摘要、匹配分析和交易意向入口。

### Step 6：与数字顾问对话

点击“问顾问”进入 `chat.html`。

默认使用本地模拟回复，不需要配置 Key。只有在聊天页配置了 OpenAI-compatible `baseURL`、`apiKey` 和 `model` 后，才会调用真实 LLM。

Key 只保存在当前浏览器标签页的 `sessionStorage`，关闭标签页后失效。正式生产环境不建议把 API Key 放在前端，应改成后端代理或临时令牌。

专业版/企业版用户可以把数字顾问加入长期顾问席位。购买单项付费专利资料/对话许可后，也会获得该专利对应的数字顾问资产，但它不占会员顾问席位。

### Step 7：提交交易意向

企业认证后，可以从推荐结果、专利详情或聊天页提交交易意向。

交易意向会保存到 `localStorage`，并在 `user-center.html#trade-intents` 中展示。正式版中，这一步应进入 CRM、商务跟进或专家服务排期。

## 5. 商业流程说明

当前商业闭环是 B + C 混合版：

1. 买方企业先注册并完成小额打款认证。
2. 企业购买买方服务包，获得更多技术需求项目、顾问席位、Token 和交易跟进权益。
3. 企业上传真实技术需求，平台围绕需求推荐专利和数字顾问。
4. 企业可以先试聊免费共享专利，降低探索门槛。
5. 对付费专利，企业购买资料/对话许可，解锁深度数字顾问问答和匹配分析。
6. 当匹配意向明确后，企业提交交易意向。
7. 后续由平台或专家团队承接真实商务流程，包括尽调、报价、合同、授权或转让。

## 6. 当前限制

- 没有真实登录系统，用户状态保存在本地浏览器。
- 没有真实支付，会员购买和许可购买都是前端模拟。
- 没有真实小额打款，认证金额由前端模拟。
- 没有真实文件上传到服务器，需求文本只在浏览器本地读取。
- 不解析 Word/PDF，第一版只支持 `.txt`、`.md` 或粘贴正文。
- LLM Key 只适合个人本机演示，不适合公开部署。
- 推荐结果依赖当前内置演示专利数据，适合产品演示，但还不是完整真实专利库。
- 交易意向不是正式订单或合同。

## 7. 如何交付给别人试用

现在不一定只能“打包发给别人”，有三种方式。

### 方式 A：打包给别人本地运行

把整个 `scholarmate` 文件夹压缩发给对方。对方解压后运行：

```bash
python -m http.server 8123
```

优点是最快，不需要服务器。缺点是对方需要会启动本地静态服务器，且数据只在自己的浏览器里。

### 方式 B：部署成静态网页

可以放到 GitHub Pages、Vercel、Netlify、学校服务器或普通 Nginx 静态目录。

优点是别人直接打开网址就能试用。缺点是目前仍然没有共享数据库，每个人的数据仍保存在自己的浏览器里。

GitHub Pages 具体步骤见：

```text
docs/github-pages-deployment.md
```

### 方式 C：做成正式产品

如果要给企业真实使用，需要补后端：

- 账号与企业认证
- 数据库保存需求、许可、会话、交易意向
- 支付与发票
- LLM 后端代理
- 文件解析服务
- CRM 或专家跟进后台
- 权限、日志和安全审计

当前版本适合作为路演、导师评审、客户访谈和产品逻辑验证原型。
